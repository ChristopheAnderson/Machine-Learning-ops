RB-MLOPS-01 — Démarrage Ordonné à Froid (Cold Start DAG) & Contrôles Quotidiens
SLA Cible : < 90 secondes · Fréquence : Quotidienne (06h00) ou après maintenance serveur
# 1. Vérifier le montage chiffré SQLCipher/LUKS et les quotas disques
df -h /srv/sovereign-data && sovereign-ctl storage verify-encryption

# 2. Démarrer les 5 services supervisés dans l'ordre strict du graphe (DAG)
# Ordre : [1] svc-01-db-vault -> [2] svc-02-registry -> [3] svc-03-inference-api -> [4] svc-04-batch -> [5] svc-05-watchdog
sovereign-ctl start --ordered --wait-healthy --timeout 90s

# 3. Exécuter la batterie de contrôles quotidiens (Sonde Audio 5s, SHA-256 Modèles, Chaîne HMAC Audit, Drift PSI)
sovereign-ctl daily-check --verify-audit-chain --synthetic-audio-probe --export-signed-report
RB-MLOPS-02 — Installation & Mise à Jour Hors Ligne par Lots (Air-Gap Release) + Rollback
SLA Cible : Zéro coupure (Blue/Green) · Rollback Transactionnel < 6 secondes
# 1. Vérifier hors ligne la signature cryptographique Ed25519 et les sommes SHA-256 du paquet
sovereign-ctl bundle verify --file /mnt/sas-airgap/sovereign-mlops-bundle-v3.2.0.tar.zst --pubkey /etc/sovereign/root_ca.pub

# 2. Décompresser dans le répertoire de version et valider les tests de non-régression hors ligne
sovereign-ctl release stage --version v3.2.0 --run-offline-regression-gate

# 3. Bascule atomique du lien symbolique de production (ou Rollback immédiat si alerte)
sovereign-ctl release promote --version v3.2.0 --atomic-symlink
# En cas d'anomalie post-bascule : sovereign-ctl release rollback --to v3.1.0 --instant
RB-MLOPS-03 — Reprise Après Incident Critique (Crash Service, Saturation GPU/RAM, Interruption Batch)
SLA Cible : MTTR < 45 secondes · Garantie Zéro Perte de Transaction
# 1. Diagnostiquer l'état des services supervisés et isoler le composant en défaut
sovereign-ctl status --all && journalctl -u sovereign-svc-03-inference-api -n 50 --no-pager

# 2. Reprise automatique du traitement par lots exactement au dernier offset validé (Idempotent)
sovereign-ctl batch resume --from-last-checkpoint --verify-part-files

# 3. Contrôler l'intégrité de la base embarquée et de la chaîne d'audit après reprise
sovereign-ctl audit-verify --full-chain
RB-MLOPS-04 — Sauvegarde Chiffrée AES-256-GCM, Restauration & Rotation des Clés (Loi 2017-20)
SLA Cible : RPO < 15 minutes · RTO < 4 minutes · Conformité Protection des Données
# 1. Exécuter une sauvegarde atomique à chaud de la base SQLCipher WAL et des configurations
sovereign-ctl backup create --mode hot-wal --cipher AES-256-GCM --output /srv/backups/airgap/

# 2. Tester la restauration complète dans un conteneur isolé (Dry-Run hebdomadaire obligatoire)
sovereign-ctl backup test-restore --snapshot latest --sandbox-verify-hmac
